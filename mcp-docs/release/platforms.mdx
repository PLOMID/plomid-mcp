---
title: "Platforms and packaging"
description: "Release build targets and the verification attached to each package."
---

The tag-triggered release workflow is configured for these native build targets:

| Target triple | Runner | Package |
|---|---|---|
| `x86_64-unknown-linux-gnu` | Ubuntu x86-64 | `.tar.gz` |
| `aarch64-unknown-linux-gnu` | Ubuntu ARM64 | `.tar.gz` |
| `x86_64-apple-darwin` | macOS Intel | `.tar.gz` |
| `aarch64-apple-darwin` | macOS Apple silicon | `.tar.gz` |
| `x86_64-pc-windows-msvc` | Windows x86-64 | `.zip` |
| `aarch64-pc-windows-msvc` | Windows ARM64 | `.zip` |

When the workflow runs, each target is compiled and packaged on its matching
runner. Package qualification runs the STDIO MCP smoke on all targets; Linux and
macOS also run the full transport contract. This workflow configuration does
not itself prove that hosted-runner jobs have passed; check the corresponding
Actions run for actual qualification evidence.

Packages contain the executable, example TOML, license notices, and CycloneDX
SBOM. Each archive has an adjacent SHA-256 checksum. The release workflow
attests and publishes artifacts when a version tag triggers it. These builds do
not bundle PLOMID, and this matrix does not claim container runtime
qualification.
